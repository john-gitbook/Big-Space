# Style guide

A style guide built from scratch. Everything here is yours: the section structure below is scaffolding, and each section's note explains what belongs there and why. Hints marked "Needs your input" show what you must customize. Delete any section you don't need.

**How the AI uses this page:** GitBook's AI editor and agent read this page, and only this page, when writing, editing, and reviewing your documentation. Pages elsewhere in this space are for people; the AI never reads them, so every rule you want enforced must appear here. This guide stands alone: the AI enforces only what's written on this page and applies no outside style rules, however common. If a convention matters to you, write it down.

**About the rule IDs:** Numbered rules (like SG-3) are the enforceable tier: the AI flags violations of them directly and cites the ID, so you can trace any flag back to the exact rule that produced it. Unnumbered guidance—like the voice description—is judgment territory: the AI applies it when writing and offers it as suggestions for human review, but never flags it as a violation. **A rule without a number is a rule the AI won't flag.** To add an enforceable rule, give it the next number after the current highest, wherever on the page the rule lives. Never renumber or reuse an ID, because past flags and your decision log refer to them. Over time, numbers won't match page order—that's normal; an ID's only job is to stay stable. (The SG- prefix is yours to change; keep it stable once you start using the guide.) Changes
